# Internal Experiment Acceptance for Vision II

This is the group's engineering checklist, not an official marking rubric or a guarantee of full marks. It operationalizes the Vision II measurements and the six report sections so that experiments can produce reviewable evidence. The course brief remains authoritative. Unknown values preserve uncertainty; they do not demonstrate that an unresolved extraction requirement is complete.

## Observation and Evaluation Contract

Use one canonical row per penalty event and keep every associated camera shot and replay grouped with it. Record raw match and clip hashes, slicing offset, source FPS, image dimensions, model hash, parameters, code hash, and the actual execution device. Confirm that frame IDs have one stated time basis. Source-video decoding, neural inference, saved-pose replay, label review, and EDA regeneration are different operations and must be described separately.

Before comparing methods, specify the definition of each measurement, the observable phase, the coordinate convention, and how unavailable observations are handled. Preserve automatic predictions alongside independent references and later corrections. A human-filled feature table is useful for evaluation and cannot be substituted for the requested scripted extraction. Describe exactly who reviewed which video and frame and when; an upstream annotation claiming user review is not an independently checked review in the current experiment.

The existing 39 events and ten foot references have been inspected during development. Their results support diagnostic comparison. They cannot retroactively become an untouched test set. Reserve new, uninspected events or a new match before future method selection, grouping all views of each event together. Synthetic controls and unit tests validate specific implementation properties, not video accuracy. Set internal acceptance tolerances before each independent evaluation and report their purpose; none is implied by the teacher's brief.

## Measurement Completion Criteria

| Requested output | Script evidence needed | Evaluation and interpretation |
| --- | --- | --- |
| Kicker run-up trajectory and bird's-eye view | Correct actor track, continuous observation intervals, supported pitch-plane correspondences and transforms, visible gaps, calibrated units and transformation quality. Ground-contact points should be used for a pitch-plane claim. | Check actor identity and reprojection error on independent observations. Image coordinates or background stabilization alone do not establish a bird's-eye pitch trajectory; hip and airborne-ball points do not lie on the grass plane. Report unavailable views and observed coverage. |
| Foot used in this kick | Anatomical left/right channels around a defensible contact/departure bracket, continuous evidence, detected channel instability, and separated motion/contact cues. | Evaluate the attempt's actual striking foot, not permanent footedness. Report decided coverage and agreement against independently reviewed attempts. An approach-side or camera shortcut is a prior, not proof of anatomical contact. |
| Run-up steps | Explicit onset/end definition, identified actor, candidate event frames, distinction between preparation, approach and striking swing, parameter sensitivity and incomplete-footage status. | Define what counts as a landing, including the final support-foot placement, before reviewing. Compare event precision/recall and count error against independent landing references. Signal extrema, stable counts, and full script completion do not establish true steps. |
| Goalkeeper movement before the kick | Correct keeper, pre-contact phase with a verified time basis, supported background compensation, and missing outputs after a broken transform chain. | Evaluate identity and trajectory error or the stated movement-category agreement. Rerun affected legacy outputs after a stabilizer repair. Pixel speed is not physical speed, and a failed transform is not zero movement. |
| Goalkeeper dive direction | Evidence from the dive phase, identity, and an explicit image-left/right or goalkeeper-left/right convention. | Match the reference's convention before counting agreement. A camera-side change can invert image interpretation; role or event ambiguity must remain visible. |
| Goalkeeper dive height | Defined physical or explicitly ordinal image-based quantity and phase, an identifiable body part or silhouette, reference scale/geometry, and evidence that distinguishes low, medium and high. | Keep strict phase height, silhouette proxies and legacy classifications separate. A proxy cannot establish missing physical height or complete the requested phase measurement. |
| Ball trajectory | Supported ball identity from contact to arrival, association continuity and branch handling, declared coordinates, and visible gaps. | Review ball versus penalty spot and other false objects. Report trajectory coverage and identity failures. Pose anchors or a nonempty polyline do not verify the ball track. |
| Ball final position | A defined event end and supported ball identity at that end; the endpoint's event frame and coordinates. | Distinguish last visible detection from actual event-final position. An occluded final state stays unavailable rather than inheriting the last detected point. |
| Goal outcome | A declared rule with ball identity and arrival/crossing evidence or an explicit abstention; separate external match references. | Verify reference event mapping and its primary source. Report rule coverage, covered confusion and abstentions. Unknown is neither a miss nor a correct negative; external results cannot be described as automatically detected outcomes. |
| Four requested camera views with start/end | Temporal intervals for the requested behind-kicker, kicker-right oblique, slow-motion kicker close-up and slow-motion goalkeeper-back views. Keep shot boundaries, spatial class, replay identity and speed evidence separate. | Independently review boundary timing, class and playback properties. Distinguish supported non-target views from uncertain views and report targets absent from the source. Finding cuts or covering the entire timeline alone does not complete semantic camera extraction. |

## Current Foot and Step Diagnosis

The inherited ten-clip high-resolution foot experiment produced ten strict-contact abstentions. Its motion statistic uses the largest adjacent ankle displacement in a short window; a single pose jump can dominate this statistic. Its nearest-ankle-to-ball proxy can instead select a planted support foot. Requiring three normal/mirrored motion and proximity labels to agree is conservative, but it does not distinguish these reasons for disagreement. The formal 39-row bundle contains nominal foot candidates for every event and only one stable result; nominal availability is therefore an unsuitable completion criterion.

The independent module `src/kicking_foot_evidence.py` uses the recorded contact/departure bracket, normalized ankle motion relative to the hips, a median speed statistic, multiple continuous frame-pair votes, two temporal windows, and inverse-mapped mirrored-channel consistency. It also flags abrupt transitions where exchanging anatomical channels gives a much smaller continuity cost; actual crossing limbs can cause similar ambiguity, so it does not apply a guessed relabeling. It never reads reviewer labels, uses approach side to break a tie, or declares actual shoe-ball contact verified. Its output is a temporal hypothesis. Conflicting windows or views, uncertain temporal channels and insufficient samples abstain. This change addresses a specific outlier failure without claiming that stronger motion always belongs to the striking foot.

The runner `scripts/analyze_kicking_foot_evidence.py` freezes predictions from the saved pose records before its optional reference comparison. It records source and code hashes and can generate source-frame sheets from original match videos using the slicing offset and local frame clock. These sheets let reviewers check whether the cached actor and channels correspond to the observed source. They do not create fresh pose inference or independently verified labels. Existing thresholds and references have already been inspected, so the comparison remains development evidence.

The canonical saved v3/v4 comparison changes 11 step outputs: eight unavailable baseline counts become candidates, while three already available counts change. It also flips 13 previously decided left/right foot candidates. The updated contact records describe 20 events as supported and 19 as tentative; neither is independently verified. These are method differences rather than demonstrated accuracy gains. The step pipeline's PCA extrema are explicitly not landing contacts. Its sensitive, central and strict counts differ across many events, and the known partial Brozovic clip cannot represent a full approach. Rashford's 15 and Pivaric's 14 are high candidate counts requiring landing review; both contact anchors are tentative. Accepting a step experiment requires inspecting onset, contact timing and actor identity first, then evaluating landing events. Replacing one pose model with a larger one must be evaluated on those properties rather than on whether a count looks more plausible.

## Current Camera Diagnosis

The recovered release contains 197 candidate intervals across all 39 events. Its spatial view candidates include 37 kicker close-ups, one goalkeeper-back view, three behind-kicker views and seven kicker-right oblique views. The remaining candidates include 76 person close-ups with unresolved identity, 47 unknown views, 23 other-left oblique views and three side-unresolved views. The 187 unknown course-class outputs mix legitimately non-target spatial views with unresolved identity or speed; they should not all be counted as false classifications.

Playback remains unknown for all 197 intervals. Of these, 159 have the reason `no_same_action_alignment_test`; 38 report `no_reliable_same_action_slowdown_evidence` after an attempted comparison. The stored role comparisons have 75 insufficient same-action alignments and one insufficient-action-variation result. The 37 kicker-close-up candidates and the one goalkeeper-back candidate therefore cannot be promoted to the two requested slow-motion classes. The first repair target is identity and comparable action support across views, followed by temporal alignment evaluation; reducing a slowdown threshold without that evidence does not resolve the missing measurement.

## Reviewable Deliverables

Each experiment should retain its exact inputs, frozen prediction rows, intermediate evidence, parameters, failure reasons and separately scoped evaluation. The formal bundle should incorporate a new result only after the group checks source identity, time basis, numerical integrity and the claimed observation scope. Rebuild all three EDA figures from that same bundle and update report text only after these checks.

The six-section report must explain related work, collection and preparation, actual EDA, two or three answerable questions, tested techniques and iteration, and the code structure. It should distinguish established results from pending measurements and disclose AI assistance and genuine group contributions. The demonstration video should show an actual source clip, script execution, intermediate evidence, an output row and a failure case. Successful installation, a private repository, or passing tests does not demonstrate accurate automatic football analysis or a submitted assignment.
